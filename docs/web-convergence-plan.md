# Web 代码收敛执行方案

- 状态：实施中；P1–P4 已完成；P5 后端业务路由已收拢，app.py 保留装配与全局规则，后续整理前端共享交互和下载模块内部重复。PWA 和内置 HTTPS 已移除，仅保留外部反向代理 HTTPS；默认只做受影响功能的关键验证，不逐批跑全量测试。P3 详情页覆盖确认后的浏览器验收受工具弹窗限制，已用前端行为验证覆盖相应状态逻辑。
- 制定日期：2026-09-19。
- 范围：Flask Web、相关 CLI、模板和静态资源、共享媒体服务、Python 测试。
- 不涉及：`apps/radio/` 的 React Native 实现、原生产品改版、发布和部署。
- 本文记录多轮讨论后的最终功能定位，取代此前“主题卡片优先下线、AI 标题归为 Beta”的提议。

## 1. 执行目标与已确定决策

以统一媒体库为基础，让 Flow 和 Gallery 使用同一批图片、视频以及同一份资源状态；Radio 只消费音频。降低核心工作流中的重复实现和隐式依赖，保留有使用价值的能力。

| 功能 | 定位 | 本次处理 |
| --- | --- | --- |
| 多源目录、普通媒体索引、缩略图 | 核心基础 | 收敛扫描、路径、查询和缓存规则 |
| 下载及媒体登记 | 核心资源入口 | 修复成功语义，整理生命周期 |
| Flow / Gallery | 同一资源的两种浏览方式 | 共享资源操作，保留各自选择、布局和交互 |
| Radio | 音频消费方式 | 保留音频播放规则，逐步使用公共媒体索引 |
| 收藏、用户集合、下载来源图集 | 稳定资源组织能力 | 保留；明确三者含义，不强行合并模型 |
| AI 标题和标签 | 稳定、常用的正式能力 | 独立业务模块，移出媒体切换必经路径 |
| Flow 主题卡片 | 正式内容发现能力 | 保留并修复分页，第一轮维持初级规则 |
| 向量构建、视觉相似搜索和相似分组 | 实验能力 | 集中隔离，可整体关闭，保留实现与数据 |
| 认证、HTTP、媒体传输与反向代理 HTTPS | 核心运行基础 | 保留认证、私有缓存、Range 和安全 Cookie 配置 |
| PWA、本地证书管理与内置 HTTPS | 已决定下线 | 删除安装入口、证书命令、专属依赖和测试；已有证书及业务数据不删除 |

Gallery 是产品层面的网格浏览方式，当前主要由 `/library` 承载；本次不恢复已删除的 `/gallery` 路由。

### 约束

1. 延续 Flask + Jinja + 原生 JavaScript + SQLite，第一轮不新增框架或任务基础设施。
2. 行为修正与纯搬迁分别交付；每个单元可独立检查，应用始终保持可运行。
3. 不删除媒体、收藏、集合、标题、向量或历史数据库迁移，不将重构变成数据重建。
4. 核心 URI 继续采用 `@source_id/relative/path`；旧裸路径和既有 URL 的兼容集中在入口，不四处复制。
5. 共享服务调整须验证已有原生 API 契约，但不借此重构原生客户端或删减其协议测试。
6. 有价值功能出现冲突时优先修正接入；仅无法隔离且实际损害核心的实验执行路径可停用，必须记录影响和恢复方式。
7. 不以文件行数、测试数量或覆盖率作为主要验收指标。

| 观察 | 证据程度 | 对计划的影响 |

| CLI / Web 缩略图键和默认取帧策略不同 | 源码确认，未实际生成比对 | 统一实现，保留显式策略差异 |
| 测试含大量 HTML、CSS、JS 源码文本断言 | 源码确认 | 删除低价值断言，保留用户行为与失败边界 |

规划时统计：13 个 Python 测试文件、119 个测试函数、约 3,406 行，包含服务端原生协议测试。上述数字不是需要达到的上限。该段为规划基线；实施结果见下方交付记录。

## 3. 目标职责与依赖方向

```text
多源文件系统 ──扫描 / 下载登记──> 普通媒体索引
                                      │
                         规范媒体记录、URI、资源操作
                           ┌──────────┼──────────┐
                         Gallery     Flow       Radio（音频）
                                     │
                               权重、混排、主题卡片

收藏 / 集合 / 标题标签：通过同一媒体 URI 关联，跨浏览方式复用
向量与相似实验：读取核心媒体能力，保存自己的结果；核心不依赖实验
```

### 目标模块：按需要迁移，不预创建空目录

| 目标位置 | 从哪里迁入 | 明确职责 |
| --- | --- | --- |
| `services/library.py` | `services/__init__.py` 的来源、URI、文件扫描 | 来源与文件边界；不承担页面混排 |
| `services/favorites.py` | `FavoriteService` | 收藏读写及失败传播 |
| `services/recommendation.py` | `RecommendService` | 候选权重；不生成页面 HTML |
| `web/flow.py` | 原 `view_builders.py` 的混排、主题、来源图集及 app.py 的 Flow 入口 | HTTP 与展示条目组合；权重仍由推荐服务负责，无独立 feed 服务层 |
| `services/captions.py` | 当前 `metadata.py` 的模型、Prompt、生成流程 | 正式标题标签业务 |
| `services/metadata.py` | 保留并收紧已有存储职责 | 旧元数据文件唯一读写入口；提供有限更新操作 |
| `services/media_info.py` | `view_builders.py` 的尺寸读取与探测 | 显式探测与基础信息更新，不藏在序列化里 |
| `web/library.py`、`web/flow.py` 等 | `app.py` 对应页面和 API | 按功能一起组织 HTTP 入口 |
| `web/media_payloads.py` | 现有重复链接与结果组装 | URI 到 URL 和展示字段的纯转换 |
| `experiments/similarity/` | `services/embedding.py`、`services/similarity.py`、相关 CLI/API | 向量与相似功能的完整实现 |
| `static/experiments/`、`templates/experiments/` | 相似功能专属界面 | 从普通 Library 中移出的页面与资源 |

独立的 `collections.py`、`library_index.py`、`thumbnail.py`、`radio.py`、认证和 TLS 模块优先沿用。下载模块只在状态与生命周期修正后，按真实职责提取工具执行或来源解析；不预建下载引擎基类。

注册方式沿用 `register_*_routes(app, ...)`，先保留 URL、endpoint 名称和 HTTP 方法。应用入口构造依赖，功能模块仅接收实际需要的对象。包入口保持简短，不把对象注册中心或通用容器作为新的依赖来源。

### 三条稳定契约

- 资源契约：身份是 URI，Flow/Gallery 的收藏、标题、集合、缩略图和删除规则一致；音频也使用相同身份规则。
- 查询契约：列表筛选和确定性排序由索引查询负责；Flow 排序由推荐与混排负责，二者不相互覆盖。
- 实验契约：只有装配入口知道是否启用实验；普通媒体服务不导入向量或相似业务模块。

### P1：修复核心边界，保留主题卡片

#### P1-A：Flow 媒体分页与卡片分离

- [x] 先构造基础媒体序列并取本页，再装配主题卡片；`page`、`has_more` 按基础媒体序列计算。
- [x] `size` 明确表示基础媒体数；主题卡片不占媒体分页额度，因此展示条目数允许超过 `size`。保留当前默认媒体页大小及 URL、响应主体字段。
- [x] 第一轮保留“最近加入”“收藏精选”，维持第一页最多一张的简单规则；不同时新增主题算法。
- [x] 卡片有独立标识，内部引用媒体 URI；卡片容器不作为媒体写入收藏、标题或消费反馈。卡片预览可重复展示媒体，不计作播放序列新增媒体。
- [x] 来源图集在本页基础媒体确定后组装：只合并本页至少两张同来源图片，不从其他页额外拉入播放成员，避免再次改变媒体游标。卡片点击查看完整帖子仍可走独立浏览入口。
- [x] 源码核对客户端以服务端页码和 `has_more` 推进，不以展示条目数量推算媒体偏移。
- [x] 桌面浏览器验证视频播放、图片切换、图集内切换、主题预览定位、收藏反馈和第二页请求；动态反馈改变排序的限制仍适用。手机触摸验收留在最终验收阶段。
- [x] 固定候选输入和 seed 时，展开图集后，每页基础媒体与插卡片前相同，页间不因装饰漏项或重复；空库、纯图片、纯视频可用。

范围说明：实时反馈、文件增删会改变推荐候选，本轮不引入持久化 Feed 会话或承诺动态库的完整遍历。固定 seed 的可复现性限定于候选和权重输入不变。主题与图集不能在此之外额外破坏分页。

#### P1-B：下载成功与登记一致

- [x] 对可识别媒体输出，发布成功前完成索引登记；登记异常或输出未登记不能被吞掉。非媒体附件不强制成为可播放记录。
- [x] 保留文件和输出列表；登记失败沿用 `failed` 状态，增加明确失败阶段（例如 `failure_stage=index`）及“文件已下载，登记失败”的信息，不新增整套状态机。
- [x] 已有重试入口识别登记失败：输出仍存在时只重试登记；成功后结束任务，不再次启动下载工具。旧历史无失败阶段时沿用现有下载重试规则。
- [x] 输出已丢失时明确说明无法仅登记，不默默把登记重试变成重新下载；用户可重新创建下载任务。
- [x] 首轮保留其他重试、取消和重启中断语义：当前重启会把 queued/running 标记为失败，并非自动续传，不顺带引入自动恢复队列。

#### P1-C：扫描失败保护

- [x] 扫描逐来源返回记录与完整完成状态；目录存在不等于扫描成功。
- [x] 一个来源任意目录枚举或必要文件读取失败时，本轮将该来源视为不完整，保留旧索引并报告错误；其他完成的来源仍可正常同步。
- [x] 仅完整完成来源允许删除未发现的旧记录；全部失败不能用空快照覆盖旧索引。
- [x] 尽量一次遍历区分图片、视频、音频，统一扩展名大小写规则；保留现有媒体类型支持及路径安全检查。

验收：三个子项分别有小规模行为测试；主题仍可展示，下载不会虚假成功，失败来源不会被误清理。行为改动和文档一起交付，不与大规模重命名混在一起。

### P2：收拢公共资源能力

- [x] 从包入口迁出来源、收藏和推荐职责，修改真实调用方；保留的临时重导出须列出消费者及移除条件。
- [x] 统一媒体 URL 组装；新结果统一使用 `/media/<path>`、`/thumb`，旧 `/media?uri=` 仍可读取。修正相似结果把原图当缩略图的生成方式。

- [x] CLI 和 Web 共用缩略图服务、规范 URI 键、有效性检查和删除方法；取帧策略显式传参，保留已有 CLI/Web 默认差异。
- [x] 对可明确归属默认来源的旧裸路径缩略图，按需校验并复用；不同来源同名文件不得错误共享缓存。保留旧映射文件，暂不做全量清理。
- [x] 收藏写入错误向调用方传播；共享前端请求检查 HTTP 失败并正确回滚乐观状态。核查相关读改写锁和原子替换边界，避免复制多套 JSON 写入工具。

### P3：把标题能力整理为正式模块

### 最小公共测试设施

优先新增/替换的高价值场景：

1. 卡片和来源图集不会改变本页基础媒体及下一页边界。

### 第七批：下载生命周期与下载路由（P5 第一阶段）
