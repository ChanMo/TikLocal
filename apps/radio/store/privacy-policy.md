# LumaFold Privacy Policy

- Effective date: 2026-08-26
- Applies to: LumaFold native app

LumaFold is a local-first app for importing and viewing media selected by the
user. It can also connect to a TikLocal Server operated by the user for the
optional Radio experience. The app does not require a TikLocal cloud account,
and the TikLocal project does not operate a service that receives the user's
media or activity.

### Local media

The user can explicitly choose photos and videos through the system Photos or
Files picker. LumaFold copies the selected items into its private app storage
and stores a local SQLite index containing file metadata such as media type,
name, size, dimensions, duration, import time, source identifier, and a path to
an on-device video preview generated by the app.

- Imported media and its index stay on the user's device and are not uploaded
  to the TikLocal project.
- LumaFold marks the directories containing imported media copies and derived
  video previews as excluded from iCloud device backup. The local SQLite index
  and preferences may still be included in operating-system backups.
- Deleting an item or clearing the library removes only LumaFold's managed
  copy and index record. It does not delete the original from Photos or Files.
- Uninstalling the app removes its managed media copies and local database,
  subject to normal operating-system behavior.

Photos permission is requested only after the user starts a Photos import.
Files access is provided by the operating system for items the user selects.

### Optional TikLocal Server and Radio

When the user pairs with a TikLocal Server, the app sends the server address,
the access password entered by the user, and a generic device name directly to
that server. The password is used only for pairing and is not saved. The user
can instead scan a one-time QR code created by the server. The camera is active
only while the scanner is open; the app does not save or send camera images.

After pairing:

- The app stores the server address, server name, device identifier, and a
  revocable device token in operating-system secure storage.
- The user-operated server stores the device name, pairing time, and a one-way
  hash of the device token.
- The app requests Radio audio, metadata, and artwork directly from that
  server. Favorites and lightweight listening events are stored there to
  improve Radio selection.

Demo Signal uses only media bundled with the app and does not require a server.

### What the TikLocal project does not collect

The production app contains no advertising SDK, third-party analytics,
cross-app tracking, or developer-operated telemetry endpoint. The TikLocal
project does not receive imported media, the local media index, server address,
access password, device token, favorites, or listening history.

### Network security

TikLocal supports HTTPS and also permits HTTP for user-controlled servers on a
trusted local network. HTTP traffic is not encrypted and could be observed by
other parties with access to that network. Use HTTPS whenever practical and do
not pair over an untrusted network.

### Retention and deletion

Disconnecting from a server clears the saved profile and attempts to revoke its
device token. The user can also revoke a paired client from TikLocal's web
settings. Changing the server access password invalidates existing tokens.

On iOS, Keychain entries may persist after uninstall and reinstall as an
operating-system behavior. A token revoked on the server can no longer access
that server even if such an entry remains. Radio feedback, favorites, and
paired-device records stay on the user-controlled server until the user removes
or resets them.

### Children

LumaFold is not directed to children and does not knowingly collect personal
information from children.
